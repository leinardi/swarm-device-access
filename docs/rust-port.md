# Rust port: design and provenance record

swarm-device-access 2.0 is a Rust rewrite of the Go daemon (about 17k lines: daemon, launcher,
cgroup v1 and BPF device filters, D-Bus reload watcher). This file is the permanent design and
provenance record of the Rust code: the design decisions with their reasons, the crates, the reuse
policy, the reuse ledger with its source revisions and justified departures, the move of the shared
code to rust-common, the 1.x fixtures, and the upstream
candidates.

- The Rust code landed beside the Go daemon phase by phase, and replaced it in one breaking
  cutover commit, which removed the Go code. The 1.x Go sources stay in the git history and in
  the published 1.x images; the last one, v1.0.3, is the Go daemon of the integration suite's
  upgrade and rollback test.
- 2.0 keeps the 1.x contract that operators depend on (the image, `launch`, the config keys, the
  labels, the `sda_` metric names, the device-filter encoding that makes an in-place upgrade or
  rollback keep every grant) and is not byte-compatible with 1.x elsewhere. The numbered intended
  differences, Q1 to Q17, are listed in the README's
  [Migrating from 1.x](../README.md#-migrating-from-1x) section. **A difference that is not
  listed there and not an improvement is a defect.** The one binary-level interop that stays
  pinned is the device-filter goldens; the other Go captures below are history.
- General Rust coding guidance lives in the maintainer's user-level skills; `AGENTS.md` records
  project rules. The porting traps found along the way were collected in a `go-to-rust-port` skill
  kept in this repository during the port and moved back to the maintainer's user skills after the field
  test.

## Design decisions

| Area | Decision | Reason |
| --- | --- | --- |
| CLI | clap 4 derive with only `--` flags, as in SSE. Before clap runs, every single-dash argument longer than one character (up to `--`, skipping a value flag's value) and every positional is refused with exit 2. Kept from 1.x: `--x=false` with every Go `ParseBool` spelling, last value wins, repeatable `--device-allow`/`--device-deny`, and "explicitly set" taken from clap's `ValueSource::CommandLine` (Go's `flag.Visit`, which counts a value equal to the default). The `launch` subcommand splits at the first `--` exactly as Go does and passes the rest verbatim. | Maintainer's choice; Q1. |
| pprof | `--debug-addr` and the `debug-addr` key still parse. An empty or absent value is accepted. A non-empty value fails at startup (exit 1, error on stderr), and on `SIGHUP` the reload is rejected as an invalid setting. | Maintainer's choice; fails closed rather than silently ignoring a listener the operator asked for. Q2. |
| Logging | `tracing` events through rust-common's `tracing-setup` (`feat(log)!`, Q13): tracing-subscriber's `text` lines or flat `json` to stdout, no target, no span fields; the daemon's subscriber is reloadable (`SIGHUP` reconfigures the format and the level through `ReloadHandle`), the launcher installs its own fixed one without a timestamp. Messages, levels and field names are 1.x's, but for `error` (was `err`). It replaced the 1.x slog-compatible logger, which the port used to keep the 1.x log bytes. | The log text is an operator contract (the tests wait on message text), not its bytes: the tests assert records through `tracing_setup::testing::Capture`, and Q13 lists what changed. |
| Errors | Hand-written error enums with a `Display` and `source` chain. Joined errors are joined with newlines. No `thiserror` or `anyhow`. | Error text is logged, so it is part of the contract, and 2.0 words it itself (Q17). Follows SSE's style. |
| Docker, daemon path | rust-common's `docker-client` (bollard 0.21.1 behind a small shared layer: the connection, a whole-call timeout, an error with a kind, the stream pumps), with only its `attach` feature (`test-util` in tests), so on a unix socket only (Go used `client.New(WithHost("unix://"+socket))`, with no `FromEnv`, TCP, TLS or proxy: no `tcp`, no `tls`, no `DOCKER_*` variable is read). `src/docker` wraps it in a `Client` (`unix(socket, call, headers)`) and offers `ping`, `container_list` (running only, no filters), `container_inspect` and `events` (`since`, plus `event` filters start, unpause, die and destroy, with no `type` filter, as in Go); every unary call is bounded as a whole by `docker_client::bounded` (bollard's own timeout stops at the response headers) and by the caller's `CallContext`; the API version is negotiated once by `GET /version` on the first call that reaches an engine (a failure is not an error). The answers are bollard's models converted to the few fields the daemon reads (`src/docker/types.rs`). The read-only contract (four calls on the client, no bollard write verb, no HTTP method) is enforced by a meta-test. | One Docker client shared with the other services, tested against a fake engine. The 1.x requests (moby's `HEAD /_ping` then `GET`, its `User-Agent`, versioned paths) are not kept (Q16). |
| Docker, launcher path | A separate module `src/launcher/engine.rs` on the same client, reached through one crate-private hook of the daemon's `docker::Client`, `Client::transport`, which hands out bollard's client: create (`?name=`, the daemon spec decoded into bollard's create model), start, attach (docker-client's demultiplexed output pump), wait (`condition=removed`, registered with the engine, its headers answered, before the call returns and so before the start is sent; a container the engine no longer has is answered as removed with an unknown status, read as 1), stop (`t=10`, bounded by the call timeout plus those seconds), remove (`force`), and list with a `name` filter. No write is retried. A meta-test (`meta/tests/launcher_boundary.rs`) allows only `src/launcher/engine.rs` to call the hook or a bollard write verb or docker-client's `attach::attach` and `attach::wait`, and only `src/launcher/**` to name the engine; the daemon, processor and observability code take only the read-only trait. bollard is named in `src/docker` and the engine only, and in `testenv` (optional, `integration` feature). | No write call is reachable from the privileged daemon path. |
| eBPF | A raw `bpf(2)` call through `libc::syscall(SYS_bpf, …)` in one audited module, `src/cgroup/bpf_sys.rs`. It covers `PROG_QUERY` (flags 0, 64 ids, retry on `ENOSPC` up to 10 times), `PROG_GET_FD_BY_ID`, `OBJ_GET_INFO_BY_FD` (xlated instructions plus `nr_map_ids` for the map-id "known" semantics), `PROG_LOAD` (`CGROUP_DEVICE`, licence `Apache`, name), `PROG_ATTACH` (`ALLOW_MULTI`, optional `REPLACE` plus `replace_bpf_fd`) and `PROG_DETACH`. The workspace sets `unsafe_code = "deny"` (not `forbid`, which `#[expect]` cannot lift); only `bpf_sys.rs` carries `#![expect(unsafe_code, reason = …)]`, and a meta-test pins that list. Every other syscall goes through rustix (`openat2` with `RESOLVE_BENEATH` and `RESOLVE_NO_MAGICLINKS`, `fstat`, `readlinkat`, `pidfd_open`, `pidfd_send_signal`, `uname`, `setrlimit` `MEMLOCK`). | Go wraps the runtime's own filter by reading its instructions back, which needs exactly these commands. aya was rejected after reading its docs: it has no ELF-less load, no `BPF_F_REPLACE`, no access to the xlated dump of a foreign program, and its `CgroupDevice::attach` returns a link id rather than doing a plain `BPF_PROG_ATTACH`. |
| BPF instructions | A plain instruction model (`op, dst, src, off, imm`, with `ld_imm64` decoded as 16 bytes so the reloadability gate rejects it rather than failing to decode). `op` is cilium's 32-bit `OpCode`, whose bits above the byte tell the decoded signed, sign-extending and atomic ops apart, since cilium's encoding and text depend on them. Jump labels are resolved in-tree: the rule builder resolves each block's jumps to the next block when it lays the program out. Decoding, encoding and the instruction text are cilium asm's in host byte order, pinned for every opcode byte by `tests/testdata/devfilter/asm.tsv`. | Ownership is decided by regenerating the wrapper and comparing bytes, so a single differing byte would turn every Go-attached wrapper into an owned-block conflict after the upgrade. |
| D-Bus | zbus (default features off, `tokio`), in the system-bus connection order godbus uses (`DBUS_SYSTEM_BUS_ADDRESS`, else `/var/run/dbus/system_bus_socket`). The same two match rules, the signal stream registered before `GetNameOwner`, and no `Manager.Subscribe` call, as in Go. The systemd phase starts with a spike; if zbus cannot reproduce the sequence, or drags in async-io, the fallback is a minimal in-tree client (EXTERNAL auth, `AddMatch`, `GetNameOwner`, signal decoding). The spike (phase 18) kept zbus, and the fallback is not needed. zbus 6.1.0 with only `tokio` adds no async-io, smol, async-std or blocking crate to the tree. On a private `dbus-daemon` watched with `dbus-monitor`, the Go watcher and the zbus spike sent the same calls in the same order: `Hello`, the two `AddMatch` with the same keys and values (zbus writes `path` after `member`, which the bus does not read as a difference), `GetNameOwner`, and no `Subscribe`. Both received a fake systemd's `Reloading` edges and its `NameOwnerChanged`. On this host's system bus, unprivileged, the spike connected, added both rules and resolved systemd's owner. A stream ends with an I/O error when the bus goes away, so the watcher resubscribes where godbus closed its channel. On a real host (Linux 7.0, systemd's owner `:1.5`), a `systemctl daemon-reload` run by hand while the spike listened delivered both `Reloading` edges (`true`, then `false`) from systemd's unique name and object path, with no `Subscribe` call. | Parity of the reload-completed edge, the owner tracking and the backoff. |
| YAML | `saphyr-parser` events (tags, anchors, styles, explicit document start), feeding an in-tree port of yaml.v3's `resolve()` and of the loader's two passes: a shape check (aliases followed with cycle detection, merge keys refused) and a strict decode (known fields, duplicate keys, one document). Accept and reject parity is checked against a Go corpus. If the syntax-error wording differs from yaml.v3's, it becomes a Q entry. | `serde_yaml_ng` runs on `unsafe-libyaml` and resolves tags differently; the loader depends on node tags. |
| Metrics and HTTP | `prometheus-client` for the registry, the counters, gauges and histogram (`DefBuckets`' bounds), typed label sets, and the OpenMetrics text encoder (`feat(metrics)!`, Q14), with service-kit's `process-metrics` collector; service-kit's `http` server (hyper, a header-read and a write-stall timeout, a bounded drain) with an axum router (`feat(server)!`, Q11): 5 s, 30 s and a 5 s drain. Any method is accepted; `/healthz`, `/readyz` (503 `not ready`) and 404 otherwise. Readiness is an injected `Arc<AtomicBool>`, and the `Recorder` owns its registry. | Same `sda_` families as 1.x. Q3 (no `go_*`), Q4 (OpenMetrics text only) and Q14. |
| Clock and runtime | An injected `Clock` (rust-common's `clock`) and `clippy.toml` wall-clock bans, as in SSE; tests run on tokio's paused clock. The runtime is service-kit's `build_runtime`, multi-thread with the worker count capped at 2 (RSS is measured in the field test). Blocking syscalls run in `spawn_blocking`, under one ownership rule: the cgroup and BPF mutation of one reconcile (pin, open, verify, `SetDeviceRules`, the ledger and cache updates) is a single blocking transaction. It owns the processor lock (a `std::sync::Mutex` taken inside the blocking closure), the pidfd, the `/proc`, `/dev` and cgroup descriptors and the program handles until it returns. Dropping its future is never what ends it: the coordinator always awaits the `JoinHandle` to completion, even after the caller's timeout or cancellation, and releases the container's reservation only then. Only the async Docker calls before and between the steps (inspect and re-inspect) are cancellable. Shutdown waits for in-flight transactions inside the one shutdown budget, as Go's `daemon.Run` waits for its goroutines, and then the runtime's shutdown runs, bounded by what is left of the budget (service-kit's `run_until_exit`). `panic = "abort"`. | Same failure semantics as Go, where the context bounds the Docker calls and the cgroup syscalls are uninterruptible. Go has no `recover` here, so a panic crashes the process and Swarm or the launcher restarts it, whereas a Rust task panic under unwind would leave a silently stuck daemon. |
| Integration harness | `testenv` drives the **host** Docker daemon, as `test/integration` does today; it is not SSE's DinD Swarm, because enforcement needs real host cgroups. It has a Go-style `-run` runner (`harness = false`, zero matches fails), envid labels and a sweep, testenv-core's since the move to rust-common. The Rust suite reads its own variable, `SDA_RUST_TEST_IMAGE`, never `SDA_TEST_IMAGE`, which `.mk/integration-test.mk` exports globally as the Go-built `swarm-device-access:integration`. Before the cutover, the Rust make target builds a throwaway `FROM scratch` image from the host-architecture static musl binary and sets `SDA_RUST_TEST_IMAGE` to it. Before running any test, the harness proves that the selected image is Rust: it runs the image with `-help`, which exits 0 in Go and is refused with exit 2 and the single-dash refusal text in Rust (Q1). A mismatch fails the run and never skips it. At the cutover, `SDA_RUST_TEST_IMAGE` is set to the image built from the Rust Dockerfile, and the same identity check stays. A cross-language test also uses the Go image, under its own variable `SDA_GO_TEST_IMAGE`: before the cutover its default is the Go Dockerfile build; from the cutover on, it is the last published 1.x image, pinned by digest. The same identity check, inverted, proves that this image is Go. | Keeps Go shipping until the cutover without ever letting a Go image stand in for Rust. |
| Meta-tests | SSE's policy: a meta-test never skips on a missing tool, and every rule has a negative control. This replaces `toolgate` and `SDA_REQUIRE_TOOLS` at the cutover. The generic checks are rust-common's `repo-meta`, run with this repository's parameters. | A gate that can pass on nothing is no gate. |
| Licence | The project stays Apache-2.0. The Rust ports of `api.go`, `ebpf.go`, `v1.go` and `v2.go` (`src/cgroup/{api,ebpf,v1,v2}.rs`) keep NVIDIA's block verbatim, the crun and runc provenance paragraph, and a modification notice under it (Apache 2.0 §4b). The header check lists those four Rust paths as the NVIDIA exception, alongside the Go ones until the cutover. Code reused from SSE and SRD is MIT-licensed, with Roberto Leinardi as sole copyright holder. Each reused file carries this project's Apache-2.0 header, followed by the provenance comment `Adapted from <repo>/<path> at <commit>, originally MIT-licensed, Copyright (c) <year> Roberto Leinardi`. The header check accepts that comment and does not require it. Reused TOML configuration carries the same header and provenance as `#` comments, although the header check does not govern TOML. | The Apache terms. The copyright holder may relicense their own MIT code, and the provenance line keeps the origin and the original licence visible. |
| Release stamps | service-kit's `buildinfo!("SWARM_DEVICE_ACCESS", …)` in `src/version.rs`: `option_env!` of `SWARM_DEVICE_ACCESS_VERSION`, `_COMMIT` and `_DATE`, with the defaults `dev`, `none` and `unknown`, an empty stamp kept (`EmptyStamp::Kept`). | Same as SSE. |
| 1.x baselines | The device-filter goldens (`tests/testdata/devfilter`) are files the 1.x Go code wrote and stay frozen: they prove the daemon recognises the wrappers 1.x attached, which is what makes an in-place upgrade or rollback keep every grant. `tests/parity.rs` compares the command line and the Engine request paths with captures of the `v1.0.3` binary; where 2.0 differs on purpose (Q1, Q6, Q16, Q17) the capture files say so. | The upgrade contract is checked against what 1.x actually wrote. |

## Intended differences from 1.x

The numbered differences from 1.x (Q1 to Q17) are listed once, in the README's
[Migrating from 1.x](../README.md#-migrating-from-1x) section, where users read them. Their
numbers are stable: the module comments, the tests and this file refer to them. A new difference
is added there, with the next number, in the commit that introduces it, and only when a test
proves it unavoidable (for example the YAML syntax-error wording, Q6).

## Reuse policy

Binding for every phase of the port, and for later changes to a reused component:

- Before designing a component, read the existing Rust code and tests listed in the ledger. Copy
  and adapt them; do not rewrite them independently. Keep their structure, naming, error handling
  and dependency choices wherever this project's contract allows.
- Every reused component gets a ledger row: source path and commit, mode (unchanged, adapted or
  new), each adaptation, and the reason for every departure. The same commit brings the source's
  tests along; this project's parity and regression tests are added on top.
- No feature has two implementations unless this file records the technical reason. The
  `adversarial-review` skill checks this.
- Shared code lives in [leinardi/rust-common](https://github.com/leinardi/rust-common). No shared
  crate was extracted during the port; after it, the components the services share moved there
  (see [Moved to rust-common](#moved-to-rust-common)). A behaviour difference between projects is
  a parameter of the shared crate, never a fork here, and a fix to shared code lands in rust-common
  first and arrives by moving the pin. Other fixes worth sending back upstream go to the
  upstream-candidates list below.
- This project's Go code stays the behavioural authority. A reference implementation never
  overrides this project's logger, error or Docker-client decisions, its log and error text, its
  Engine request contract, or its security boundaries.
- Sources are pinned: swarm-scheduler-exporter (SSE) at `d57dcc220d29` and swarm-rootless-docker
  (SRD) at `16913a4d87d8`, both MIT-licensed by the same author; rust-common by the release tag in
  the root `Cargo.toml`. A later upstream commit is taken only by updating the ledger.
- Every reused file carries this project's Apache-2.0 header followed by the provenance line (see
  *Licence* above).

### Shared release and image snippets

The release-packaging row above now uses make-common v1.14.0's `rust-release.mk` and
`image.mk`, fetched through `MK_COMMON_FILES`, rather than local adaptations. Their defaults
retain the release assets, checksums ordering and image coordinates. The Makefile owns the
toolchain pins, target mappings, checksum coverage and output directory with `:=` assignments
so environment variables cannot replace them, and maps the
existing `PREBUILT_IMAGE` override to the shared per-image setting. The shared snippet
also exposes per-image targets and `rust-zigbuild-install`; its full image tier is host-only,
with `IMAGE_TEST_TIER=reduced` for foreign platforms. The bootstrap also refreshes `password.mk`
to the released bounded-input password pipeline.

The image-test script, Docker runner, integration harness, dependency audit and verification
targets remain local because they encode this daemon's runtime and repository policy.
`image-policy.mk` rejects image gates with an empty `DOCKER_TARGETS`, rather than reporting
success without testing anything. The toolchain meta-tests read the Makefile's pins and retain
their negative controls.

## Upstream candidates

Fixes found during the port that are worth sending back to SSE or SRD. The three code fixes are
in rust-common's crates, which carry this repository's fixed copies.

- SSE `src/metrics/mod.rs`, `Registry::register`: descriptor callbacks run under the registry
  mutex and deadlock when they inspect their own registry. Fixed here by snapshotting descriptor
  names before locking and caching them for atomic duplicate checks and name queries. Landed in rust-common.
- SSE verification should run rustdoc with warnings as errors, in addition to rustfmt and Clippy;
  the duration link needs `format()` and public docs should not link private implementation items.

- SSE `src/docker/client.rs`, `ping`: the `GET /_ping` fallback drops its response unread, so
  hyper closes the connection where moby's `ensureReaderClosed` drains the body and reuses it.
  Found by replaying the Go daemon's ping-fallback capture; fixed here by draining up to 512
  bytes. Landed in rust-common.
- SSE `src/server.rs`, `parse_port`: a service name (`:http`) is refused, where Go's
  `LookupPort` without `/etc/services` (the `dhi.io/static` image has none) resolves the 14 TCP
  names of its built-in table, case-insensitively. Found by running a static Go binary in
  busybox; fixed with Go's table. Landed in rust-common.
